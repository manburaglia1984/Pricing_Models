Every block prices off the total. A row's Payment Date is its own Issue Date + tenor; open Detail to itemise it.
How the CSVs are read

There are two uploads. Here, at the group level: invoice number, supplier name, jurisdiction, issue date, tenor days, amount — one row per invoice. Add item, quantity, unit price (and optionally line total, vat, freight, insurance, other costs) and the file may carry several invoices and their items at once: rows sharing an invoice number become one invoice, one item per row, and its total is derived from them. A group in such a file with no item rows falls back to its amount cell, so itemised and flat invoices can travel in one file. Inside an open Detail row: the same item columns for that one invoice, with no invoice columns needed.

Give a payment date instead of a tenor and the tenor is worked out from it. Jurisdiction takes a code (BR) or a name (Brazil); dates, amounts and delimiters are read as loosely as on the curve upload. An item row naming a charge — VAT, Freight, Insurance, Other costs — is read as that charge rather than as goods, which is how most invoice extracts list them.

How a trade picks its curve, and how uploads are read

A trade prices off the latest curve published on or before the date it reads — the Trade Submission Date for panels 3 and 4, the Pro Forma Issue Date for panel 2. There is one curve per index; the pro forma block simply reads it at its own issue date.

CSV columns are date plus the pillars the selected index publishes — 1m,3m,6m,12m for Term SOFR, 28d,91d,182d for TIIE, and so on; the template always matches. Columns belonging to another index are ignored and named in the confirmation. Dates may be 2026-06-22, 6/22/2026, 22/06/2026 or 22-Jun-2026 — whatever Excel left behind — and semicolon files with comma decimals are read too. A row replaces any existing curve for that date.

About refreshing from monday.com

A refresh asks for a monday.com API token, uses it for that one request and never stores it — not in this file, not in localStorage. Because the token grants full account access, prefer Import JSON or a server-side sync for shared copies. Browsers block the direct call from a file:// page; serve this file over http(s) for it to work.

Holiday calendars

How the pasted list is read

One date per line, or separated by commas, semicolons or tabs. Dates are read as loosely as on the curve upload — 2027-01-01, 01/01/2027, 1-Jan-2027 and Excel serials all work, and day-first vs month-first is settled across the whole list at once. Weekends are already handled, so holidays alone are enough.

Put ? after a date — 2027-02-08 ? — for one the publisher has not confirmed. An estimate still counts as a non-business day, but a maturity date landing on it warns rather than blocking outright.

Marking a holiday as an estimate

Put ? after a date — 2027-02-08 ? — for a holiday that is on the calendar but not yet confirmed: a lunar or Islamic date, or a year the publisher has not gazetted. An estimate still counts as a non-business day, but a maturity date landing on one raises an acknowledgeable warning instead of the hard block a confirmed holiday gives. Unmark it once confirmed and it blocks like any other.

You are editing one year at a time; every other year is left exactly as it is. Dates are read in the same formats as everywhere else. Revert to shipped drops every edit for this jurisdiction and puts the build's own calendar back.

How coverage works

Coverage is the last known-good date per jurisdiction. A maturity date beyond coverage hard-blocks pricing — it is never silently passed. Which calendars apply is set per deal, on Deals & Trades. Source URLs are the official publishers; replace them with the verbatim URLs recorded as cell notes on BD Dates!B19:E19 if those differ.

What an investor is used for

An investor is a funding counterparty. Naming one here makes it a suggestion on a trade's Funder field, which is what titles that trade's Settlement Date, Margin and Cost of Funds rows. The field stays free text, so a one-off funder can still be typed straight into a trade without being added here first.

Currencies is a capability, not a preference: leave it empty and nothing is checked, but list currencies and a trade whose deal is in any other currency is blocked outright. Discount is the shape of the arithmetic panels 4 and 5 apply — the rate and day count still come from the trade's own panels. A funder that is not on this list prices under the simple discount, which is what every trade did before conventions existed.

Removing an investor is refused while a trade still names it.
